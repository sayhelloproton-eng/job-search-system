# 04｜Backend Production Completeness / System Design

## JD 为什么问

当前高匹配岗位普遍要求“能独立闭环”而不是只写一个模型调用脚本。Ownership 在 REQ_GATE 中约 71%，因此面试会追到 API、数据、权限、失败、部署、日志等完整责任链。

## 一张完整后端图

```text
React UI
  │ POST /runs
  ▼
Node API ── Auth / Tenant / Rate Limit
  │
  ├── Relational DB: run / tool_call / audit / document
  ├── Python AI Service: retrieval/model
  ├── Tool Runtime: read/write actions
  └── Queue/Worker: long-running work
  │
  └── SSE events ─────────────→ UI
```

## REST / SSE / WebSocket

- REST：请求/响应、创建资源、查询状态，简单可靠。
- SSE：服务端→客户端单向流，适合 Agent token/event/progress；天然 HTTP 语义，浏览器支持简单。
- WebSocket：双向长连接，适合双方都需要高频主动推送/控制；连接状态、扩缩容、重连更复杂。

常见回答：创建 Agent run 用 REST，增量 token/progress 用 SSE；只有真正需要双向低延迟交互时再选 WebSocket。

## 数据模型

至少能解释：`user`、`tenant`、`session`、`run`、`run_step`、`tool_call`、`audit_event`、`document`。重要字段通常包括 status、version、idempotency_key、created_at/updated_at、correlation_id。

关系库关注 transaction、unique constraint、index、pagination、foreign key、optimistic version；不要只会“建一张 messages 表”。

## Tool Side Effect 与幂等

最危险的误区是“失败就重试”。外部写动作与 DB 无法天然在一个 ACID transaction 中，需要：

```text
persist intent/idempotency key
→ execute external action
→ persist outcome
→ retry 时先查 previous outcome
→ uncertain state 进入 reconciliation/manual recovery
```

可配合 outbox、saga/compensation，但要按业务复杂度选择。
## Auth / Tenant / ACL

Authentication 回答“你是谁”；Authorization 回答“你能做什么”。Agent 系统还要把 permission 延伸到 tool/action/resource。不能只在 prompt 中说“不要访问其他租户”。

多租户最低要求：tenant_id 进入数据模型和查询边界；RAG retrieval 做 ACL filter；危险 tool 做 action policy；audit 记录 actor/resource/action/result。

## Long-running / Queue

模型、RAG、代码执行可能是秒到分钟级任务。不要让所有任务绑定 HTTP request 生命周期。需要理解 run 状态、queue、worker、retry budget、dead letter、cancel、timeout、progress event。

什么时候不用队列：任务短、同步完成、失败语义简单时。引入 queue 会增加一致性、观测和运维成本。

## Observability

最小三件套：structured logs、metrics、traces/correlation id。Agent 还应记录 model/tool/retrieval step、latency、error category、token/cost（若允许）、final status，但不要记录敏感 prompt/code/secret。

## 高频面试题

**Q1：SSE 和 WebSocket 怎么选？** 先从通信方向与状态复杂度回答，再谈浏览器重连、代理兼容、扩缩容。Agent 单向 event stream 通常优先 SSE。

**Q2：怎样保证 Tool 不重复执行？** idempotency key + durable tool_call record + unique constraint/status；重试前读取旧结果。对于第三方系统还要结合其幂等接口或 reconciliation。

**Q3：事务提交了但外部 API 失败怎么办？** 不能声称一个本地事务能覆盖外部系统；明确状态 `PENDING/EXECUTING/FAILED/UNKNOWN/SUCCEEDED`，用 outbox/worker/compensation/manual reconciliation 收敛。

**Q4：Agent 服务怎么做多租户？** 身份→tenant context→DB row/query scope→retrieval ACL→tool policy→audit；任何一层都不能依赖模型自觉。

**Q5：高并发先优化哪里？** 先测瓶颈。Agent 常见瓶颈是 model latency/rate limit、retrieval、连接池和 long-running concurrency。再决定 cache、queue、rate limit、worker scale、bulkhead/circuit breaker，而不是先上 K8s。

## 系统设计题

设计一个“AI 代码审查平台”：PR 创建后触发 Agent，检索代码/规范，调用静态分析与测试工具，输出 review；高风险自动修改需人工审批。回答覆盖 webhook/idempotency、run state、queue、RAG、tool permission、audit、SSE/status、retry、failure isolation。

## 你的证据映射

DIRECT/TRANSFERABLE：云平台、复杂中后台、私有化、多环境、监控/告警、usage-reporter 的 outbox/脱敏/remote client、质量 Gate。面试应优先用这些真实工程事实解释 production mindset，再用学习项目补 Agent backend 具体实现。

# 06｜Testing / Eval / CI / Docker / Reliability

## JD 为什么问

Testing/Quality 在 REQ_GATE 约 53%，而你的直接优势本来就包括 Quality Gate/Evaluation。面试目标不是证明“会写测试”，而是证明你知道普通软件测试和 AI Eval 分别防什么风险，并能把它们放进交付 Gate。

## 测试分层

```text
Unit
  ↓ 纯逻辑
Contract
  ↓ Tool/API/schema
Integration
  ↓ DB/vector/model adapter
AI Eval
  ↓ retrieval/grounding/task quality
State Recovery
  ↓ interruption/retry/idempotency
Browser E2E
  ↓ 用户主链路
Deployment Gate
```

没有一种测试能覆盖所有风险。

## 普通测试 vs AI Eval

普通测试适合确定性 contract：状态转移、权限、schema、HTTP code、幂等、数据写入。

AI Eval 适合概率质量：retrieval recall、groundedness、task success、tool selection、refusal、latency/cost。Eval 数据集必须有版本和回归基线，不能只人工看几个 demo。

## Agent 特有测试

- Tool contract：schema、参数校验、错误映射、副作用幂等。
- Retrieval eval：gold query→expected evidence。
- Trajectory/step：是否选对工具、是否出现不允许步骤。
- Recovery：中断后是否从正确 checkpoint 恢复。
- Permission：越权检索/写操作必须失败。
- Regression：Prompt/model/framework 升级后关键 case 不退化。

## CI Gate

典型链：`format/lint → unit → contract/integration → eval threshold → build image → security/config checks → deploy staging → health/readiness → smoke → promote`。

不是所有 eval 波动都应该阻止发布；需要给 critical case 更高权重，并结合阈值、趋势和人工 review。
## Docker / Health / Ready

Docker 面试不要停留在“写过 Dockerfile”。要解释 image/container、network、volume、env/config/secret、non-root、build cache、multi-stage build，以及服务依赖。

`/health` 回答“进程是否活着”；`/ready` 回答“是否具备接流量条件”。例如 API 进程活着，但 DB/vector store 初始化失败，应 health=alive、ready=false。

## 高频面试题

**Q1：AI Eval 和普通单测有什么区别？** 普通测试验证确定 contract；AI Eval 衡量概率性质量。一个 Agent 系统两者都要，不能用 eval 代替权限/事务测试，也不能用单测证明回答质量。

**Q2：Prompt 改了一行怎么知道没有退化？** 固定版本化 eval set，跑关键任务成功率/grounding/retrieval/tool selection，再比较 latency/cost；critical case 失败直接阻断。

**Q3：模型结果不稳定，CI 怎么设 Gate？** 对 deterministic 部分做硬 gate；对概率 eval 用多样本、阈值/置信区间或稳定 benchmark，critical safety case 做硬失败，非关键质量指标可做趋势/人工 review。

**Q4：Health 和 Readiness 区别？** health 用于判断进程是否需要重启；readiness 决定能否接收流量。依赖未准备好时不要因为进程活着就宣称 READY。

**Q5：线上 Agent 失败怎么定位？** 先拿 run/correlation id，把 UI→API→retrieval→model→tool→DB 的 trace 串起来；按 error category 和 latency step 定位，不从日志海里猜。

## 故障注入清单

1. Vector store timeout；2. Model 429；3. Tool 返回 500；4. Tool 实际成功但 response 丢失；5. DB connection exhausted；6. 未授权 document；7. 进程在 WAITING_APPROVAL 后重启；8. SSE 客户端断线。

面试里如果能讲“我会主动注入哪些失败以及期待状态是什么”，比单纯说“做了测试”更有说服力。

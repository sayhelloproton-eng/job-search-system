# Learning System｜学习系统设计

Learning 是 Job Search System 的正式产品模块，不是个人学习笔记的别名。

它负责把岗位、面试和公开技术知识中的学习信号转成结构化、可追踪、可复习的学习状态，同时严格阻止“学过”被自动写成“做过”。

## 1. 模块组成

```text
Term Graph
  ↓
Term Card / Prerequisite / Relation
  ↓
Course Unit
  ↓
Learning Runtime
  ↓
Progress / Review Queue
  ↕
Interview Feedback Bridge
```

- **Term Graph**：统一术语、别名、前置关系、上下游关系和易混概念。
- **Term Card**：解释一个概念是什么、为什么存在、如何工作、何时使用以及主要 trade-off。
- **Course Unit**：把多个术语组织成一组可解释、可实践、可排错、可设计的能力。
- **Learning Runtime**：提供查询、路径规划、进度记录、复习和反馈接口。
- **Interview Feedback Bridge**：把面试暴露出的知识缺口变成学习输入，学习完成后再进入复练队列。

## 2. 学习状态

统一掌握梯度：

```text
UNSEEN
→ RECOGNIZE
→ EXPLAIN
→ CONNECT
→ APPLY
→ DEBUG
→ DESIGN
→ INTERVIEW_READY
```

状态描述的是“当前掌握程度”，不是工作经历等级。

- `learning.record_term_progress`
- `learning.get_term_progress`

## 4. 数据与 Truth 边界

公开仓中的术语和课程数据位于：

```text
app/server/data/learning/terminology/
app/server/data/learning/course/
```

这些数据是 synthetic / generic fixture，用于 fresh clone、测试和产品演示。

SQLite migrations 定义 Learning Progress、Review 与 Calibration 的数据结构；真实个人进度属于本机 runtime DB，不进入 Git。

固定真值边界：

```text
Course / Term Content   = learning content truth
SQLite Progress         = user learning state
Interview Observation  = learning input signal
Career Facts / Evidence = historical experience truth
```

Learning Runtime 可以更新学习状态，但不得修改 Career Facts，也不得把 `LEARNED`、`INTERVIEW_READY` 等状态解释为生产经验。

## 5. 与 Interview 的闭环

```text
Interview Observation
→ Knowledge / Expression Gap
→ Term / Course Mapping
→ Shortest Learning Path
→ Practice / Review
→ READY_FOR_REVIEW
→ Interview Review Queue
→ Re-interview
```

系统必须区分候选人知识缺口与题库、评分、Director 策略问题；只有真正属于学习的问题才进入 Learning Queue。

## 6. Public / Private Boundary

公开：

- Learning Runtime 源码；
- Learning migrations；
- synthetic / generic Term 与 Course fixture；
- 本文件这份模块级设计。

私有：

- 个人学习优先级与差距矩阵；
- 真实 JD 驱动的个人课程排序；
- 候选人能力快照；
- 个人学习进度与复习历史；
- 内部调研、实施过程和验收记录。

这样公开仓提供完整的 Learning 架构与可运行能力，同时不携带任何作者个人学习档案。

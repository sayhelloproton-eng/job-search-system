# 术语学习系统｜Term Graph Learning System

> 日期：2026-09-08
> 状态：**SYSTEM_DESIGN_V1 / T1_CANONICALIZATION_PASS / T2_TERM_GRAPH_PASS / T3_LEARNING_RUNTIME_CURRENT**

## 1. 目标

这不是 A-Z 技术词典，也不是把面试八股换成术语卡片。

目标是把当前求职学习涉及的专业概念组织成一张**可渐进学习、可追溯来源、可从面试反馈自动回流的术语知识图谱**。

四条主链固定为：

1. `Agent`：模型 → Context → Retrieval/Memory → Tool/MCP → Runtime → Workflow/Multi-Agent → Eval/Guardrail/Tracing；
2. `Frontend`：Web → Browser → JavaScript Runtime → Framework → Engineering → Performance/Test/Security；
3. `Backend`：Server Runtime → API → Data/DB → Async/Concurrency → Queue/Worker → Reliability/Observability → Deployment；
4. `Full-stack`：Client↔Server 契约 → BFF/Auth/Data Flow → SSR/Streaming/Cache → End-to-end Reliability/Delivery。

FDE、RAG、Docker、数据库、可靠性等不再作为与四条主链平级的第五/第六条路线，而作为跨链能力域挂接。
## 2. 一个术语必须回答什么

每个 `Term Card` 固定包含：

1. `canonical_name / 中文名 / aliases`：统一名词，解决同义词和框架别名；
2. `白话定义`：一句话说清它是什么；
3. `背景 / Why`：它为什么出现，之前什么问题推动了它；
4. `解决的问题`：它真正解决什么，不解决什么；
5. `核心机制`：内部怎么工作；
6. `系统位置`：位于浏览器、Server、Agent Runtime、DB、Infra 还是协议层；
7. `作用`：对正确性、性能、可靠性、开发效率或产品体验的具体作用；
8. `前置概念`：学它之前必须先懂什么；
9. `上下游关系`：它调用谁、被谁消费、和哪些概念组合；
10. `易混概念`：例如 Context vs State vs Memory，Tool Calling vs MCP；
11. `何时用 / 何时不用`；
12. `Failure / Trade-off`：最常见失败和代价；
13. `最小实例`：代码、系统图或现实例子；
14. `面试表达`：30 秒定义 + 深挖追问入口；
15. `Source / Freshness`：定义来自哪里、是否随版本变化；
16. `Candidate State`：DIRECT / TRANSFERABLE / LEARNING_GAP / STRUCTURAL_RISK；
17. `Learning State`：当前掌握到什么深度。
## 3. 图谱关系

术语之间至少支持这些边：

- `PREREQUISITE_OF`：前置，例如 HTTP → REST；
- `PART_OF`：组成，例如 Tool → Agent Runtime；
- `USES`：依赖，例如 RAG → Embedding；
- `PROVIDES`：提供，例如 MCP Server → Tools / Resources / Prompts；
- `CONTRASTS_WITH`：易混，例如 SSE ↔ WebSocket；
- `ALTERNATIVE_TO`：替代方案，例如 CSR ↔ SSR；
- `IMPLEMENTED_BY`：抽象到框架，例如 Durable Execution → LangGraph Checkpoint；
- `OBSERVED_BY`：观测，例如 Agent Run → Trace；
- `FAILURE_RELATED`：故障关联，例如 Retry → Retry Storm；
- `CROSS_CHAIN`：跨链，例如 SSE 同时属于 Backend / Full-stack / Agent streaming。

因此学习入口不是“打开第 73 个词”，而是：

```text
用户问 MCP
→ 检查 Tool / Client-Server / JSON-RPC 是否掌握
→ 补必要前置
→ 学 MCP Host/Client/Server
→ 再展开 Transport / Tools / Resources / Prompts / Authorization
→ 回到 Agent Runtime 看 MCP 在整个系统中的位置
```

## 4. Learning State

`UNSEEN → RECOGNIZE → EXPLAIN → CONNECT → APPLY → DEBUG → DESIGN → INTERVIEW_READY`

- `RECOGNIZE`：见过，知道大概是什么；
- `EXPLAIN`：能用自己的话解释；
- `CONNECT`：能说清和上下游的关系；
- `APPLY`：能在实验或项目中使用；
- `DEBUG`：知道失败时从哪里排查；
- `DESIGN`：能做方案选择和 trade-off；
- `INTERVIEW_READY`：能在追问下稳定表达。
## 5. 系统输入

术语不靠人工随意扩张，来自四类真实信号：

1. **JD**：目标岗位出现的新术语与高频能力；
2. **Interview**：模拟/真实面试中出现的不会、混淆、解释不清、错误类比；
3. **Career Evidence**：已有项目中真实使用过、但机制没有讲透的概念；
4. **Curriculum / Official Docs**：已有学习内容与官方规范补齐基础链路。

输入先经过 `Normalize → Alias Merge → Chain Classification → Prerequisite Linking → Priority`，再进入学习队列。

## 6. 与面试成长系统闭环

面试导演后续必须把问题分成至少四类，不能把所有失败都归给用户：

- `CANDIDATE_KNOWLEDGE_GAP`：知识或术语真的不会；
- `CANDIDATE_EXPRESSION_GAP`：知道但表达不稳；
- `QUESTION_CORPUS_GAP`：题目覆盖、难度、评分素材有问题；
- `DIRECTOR_POLICY_GAP`：追问、切阶段、Signal 判断、时间控制不真实。

只有前两类进入个人学习/表达队列；后两类要求系统自己调整题库或 Director，并经过回归验证。

当 `CANDIDATE_KNOWLEDGE_GAP` 命中一个术语时：

```text
Interview Observation
→ Term Gap
→ 找 prerequisite
→ 生成最短学习路径
→ 学习 / 实验 / Debug
→ Term State 更新
→ READY_FOR_REVIEW
→ Interview Review Queue
→ 再面一次验证
```

这就是 P6-8 以后应该具备的“导演自我感知 + 学习系统回流”。
## 7. 来源与真实性规则

术语定义优先级：

`Protocol / Standard / Official Docs > Framework Official Docs > Maintainer Docs > 高质量工程资料 > 社区解释`。

当前第一批真源：
- Agent：OpenAI Agents SDK、MCP Specification；
- Web/Frontend：MDN Web Docs、React 官方文档；
- Backend：Node.js、PostgreSQL、FastAPI 官方文档；
- Delivery：Docker 官方文档；后续按需要加入 Kubernetes / OpenTelemetry / OWASP。

框架文档用于解释“这个框架怎么实现某个问题”，不能反过来把框架名冒充基础原理。

术语还要区分：
- `STABLE_CONCEPT`：HTTP、Transaction、Index、Event Loop 等长期稳定概念；
- `EVOLVING_STANDARD`：MCP、Web 平台新能力等需版本追踪；
- `FRAMEWORK_SPECIFIC`：React Server Components、LangGraph Checkpointer 等；
- `MARKET_TERM`：JD/社区常用但边界可能含糊的名称。

## 8. 实施阶段

### T0｜Research + Taxonomy Freeze
冻结四条主链、Term Card schema、Graph edge、来源规则和学习状态。

### T1｜Term Corpus V2
先做高召回候选池：现有 JD、学习内容、82 题、项目 Evidence、官方资料，以及 `ai-modern-evolution` 的七层 AI 工程知识树统一进入术语发现；当前已扩到 1,400+ 候选。随后必须做 Alias Merge / Canonicalization / Prerequisite Audit，不能把候选池数量直接当成学习量或完成度。

### T2｜Term Graph V1
建立 prerequisite / part-of / contrast / cross-chain 关系，保证任意核心术语都能向前找到基础、向后找到应用。

### T3｜Learning Runtime
支持 `查一个词 / 从零学一条链 / 根据 Gap 生成最短路径 / 到期复习`。

### T4｜Interview/JD Feedback Integration
面试 Knowledge Gap 和新 JD 自动进入 Term Inbox；学习结果回到 Interview Review。

### T5｜长期校准
真实面试、JD 和技术标准变化只做增量更新；不因为框架改名推翻整个图谱。

## 9. V1 验收标准

- 四条链路都有清晰起点、主干和跨链连接；
- 核心术语不存在“只有定义，没有背景/作用/关系”的空卡；
- 任意术语都能回答“为什么出现、解决什么、和谁相关”；
- 易混概念有显式 `CONTRASTS_WITH`；
- 面试发现的术语 Gap 可以定位到图谱节点与前置节点；
- 已有 DIRECT Evidence 的概念不会被当零基础重新学习；
- 学会一个术语不自动升级成历史生产经验。

一句话：**不是背 200 个名词，而是把四条技术链真正连成脑中的系统。**

# T4｜Interview / JD Feedback Integration SDD

> 日期：2026-09-08
> 状态：**T4_SDD_FROZEN / DETERMINISTIC_MAPPING_ONLY / NO_NEW_MIGRATION**

## 1. 目标

把真实求职信号接入 Term Graph，但不让反馈反向篡改 canonical knowledge。

固定链路：
`Interview Gap / JD → deterministic mapping → Canonical Terms → current progress → learning path`。

T4 只发现和规划学习需求；真正修改掌握状态仍只能通过 T3 `learning.record_term_progress`。

## 2. Interview Authority

`interview-topic-term-map-v1.json` 是 Topic→Term 的人工冻结映射：
- 41 个技术 Topic → 125 个 canonical term references；
- 11 个 `career.* / project.*` Topic 显式 `NON_TERMINOLOGY`；
- Question Family 先通过已有 `interview_family_topic_links` 找 Topic，再映射 Term；
- 未映射技术 Topic 必须返回 `UNMAPPED`，禁止 LLM 猜测。
## 3. Runtime Operations

新增只读操作：
1. `learning.plan_interview_handoff`：读取 OPEN/DONE learning handoff，解析 Topic / Question Family，返回 term targets + current progress；
2. `learning.map_jd_terms`：输入 `jobId` 或 `text`，只按 canonical/alias 明确出现做术语命中，返回 term + current progress。

不新增任何写操作；T4 不产生 Career Fact、Resume Evidence、Interview Score 或 Term Progress。

## 4. JD Mapping Rule

- `jobId` 从现有 `jobs.jd_text` 读取；允许直接传 `text` 做预览；
- canonical/alias 使用大小写不敏感的边界匹配；
- 结果按实际命中、P0/P1 与名称稳定排序；
- 不做 embedding/LLM semantic guess；未显式出现就不宣称 JD 要求该术语；
- `state != INTERVIEW_READY` 只表示当前个人学习状态，不等于岗位不匹配。

## 5. Gate

必须验证：52 Topic mapping 全覆盖、125 term refs 全存在、Question Family→Topic→Term、NON_TERMINOLOGY fail-closed、JD canonical/alias 命中、无虚构命中、progress 只读、Career Facts 0 mutation、旧 Bridge/T3 回归。

# Term Card Sample｜MCP

> 类型：`EVOLVING_STANDARD`
> 主链：Agent；跨链：Full-stack / Backend
> 学习优先级：P0

## 白话定义

MCP（Model Context Protocol）是一套让 AI 应用以统一协议连接外部能力和上下文的 client-server 协议。

它解决的不是“怎么让模型变聪明”，而是：**AI 应用怎样发现、读取和调用不同外部系统，而不用每接一个系统都发明一套私有连接协议。**

## 背景 / Why

Agent 需要文件、数据库、浏览器、SaaS API、内部系统等外部能力。没有统一协议时，每个 AI Host 都要自己定义插件格式、发现方式、调用协议和连接生命周期，生态无法互通。

MCP 把这类连接抽象为标准 participant、data layer 和 transport layer。

## 核心角色

`MCP Host → MCP Client → MCP Server`

- Host：AI 应用本身，管理一个或多个 MCP Client；
- Client：维护到某一个 Server 的连接；
- Server：向 Client 暴露上下文与能力。

一个 Host 连接三个 MCP Server，通常意味着内部存在三条独立 Client↔Server 连接。
## 核心机制

当前官方架构把 MCP 分成两层：

- Data Layer：基于 JSON-RPC 的消息、能力发现和核心 primitives；
- Transport Layer：连接、消息传输、认证与安全通信。

Server 侧核心 primitives：

- `Tools`：可执行动作；
- `Resources`：可提供给 AI 的上下文数据；
- `Prompts`：可复用交互模板。

Transport 当前重点是：
- `stdio`：同机进程通信；
- `Streamable HTTP`：远程 HTTP 通信，并支持流式能力。

## 它在 Agent 系统里的位置

```text
LLM / Agent
   ↓ 决定需要外部能力
Agent Runtime / Host
   ↓
MCP Client
   ↓ protocol + transport
MCP Server
   ↓
Tool / Resource / Prompt
   ↓
文件、数据库、SaaS、浏览器、本机程序……
```

MCP **不是 Agent Runtime**：它不负责完整 Agent loop、任务规划和长期状态；官方也明确 MCP 只关注上下文交换协议，不规定 AI 应用如何使用 LLM 或管理获得的 context。
## 前置概念

至少先理解：`Client-Server / Protocol / JSON-RPC / Tool / Schema / Authentication / Transport`。

如果这些基础不稳，直接学 MCP 很容易变成只会背“Host/Client/Server”。

## 易混概念

- `Function Calling vs MCP`：Function Calling 是模型/Runtime 表达和执行工具调用的一种机制；MCP 是 AI 应用与外部能力之间的标准连接协议。
- `MCP Tool vs Agent Tool`：MCP Tool 是通过 MCP 暴露出来的 tool；Agent Runtime 还可以同时拥有本地 Function Tool、Hosted Tool 等其他工具来源。
- `Resource vs Tool`：Resource 主要提供上下文数据；Tool 主要执行动作。
- `MCP vs Plugin`：Plugin 是更宽泛的扩展机制，MCP 是具体协议标准。

## 何时值得用

适合：多个 AI Host 需要复用同一能力、工具生态需要发现/连接标准、远程或本地能力需要统一暴露。

不一定值得：只有一个应用、一个简单内部函数，并且没有跨 Host/跨进程/标准化需求时，普通 Function Tool 可能更简单。

## Failure / Trade-off

要关注：连接失败、协议版本不兼容、tool schema 漂移、超时、权限过宽、远程认证、Tool 副作用重试、Server 不可用、能力发现 stale。

MCP 统一的是连接方式，不自动替你解决业务权限、幂等、事务或 Agent 状态恢复。

## 30 秒面试表达

MCP 是 AI 应用连接外部上下文和能力的标准 client-server 协议。Host 通过一个或多个 MCP Client 连接 MCP Server，Server 可以暴露 Tools、Resources、Prompts；协议层负责发现和调用语义，transport 负责实际通信。它解决的是 AI 工具生态的标准化连接问题，不等于 Agent Runtime 本身。

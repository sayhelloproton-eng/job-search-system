# 面试成长系统 ↔ 学习系统桥接契约

> Status: **BRIDGE_V1 / ACTIVE / TERMINOLOGY_AND_COURSE_RUNTIME_AVAILABLE**

## 1. 定位

桥只负责跨系统交接，不定义学习系统内部课程、知识模型或实验数据库。

```text
Interview D / LEARNING
→ Learning Inbox
→ Learning System
→ Learning Result
→ Interview Review Queue
→ Re-interview
```

## 2. Interview → Learning

调用 `learning.list_interview_handoffs`。只返回 `OPEN + next_action=LEARNING`，并保留 trainingEventId、Session、Route、Scene、Job、Target、observation 与时间。

Target 若原始 Feedback 使用通用 `LEARNING` 类型，Bridge 会在现有 Topic / Question Family 中解析出更具体的目标类型；不修改旧 Feedback Schema。

## 3. Learning → Interview

调用 `learning.record_interview_handoff_result`，结果只有三种：
- `PARTIAL`：仍需学习，Handoff 保持 OPEN；
- `BLOCKED`：存在依赖或无法完成，Handoff 保持 OPEN；
- `READY_FOR_REVIEW`：学习阶段完成，Handoff 标 DONE，并创建 Interview Review Queue。

结果可携带 `artifactRefs`，但这些引用只是学习产物，不是 Career Evidence。

## 4. 不变量

- request-id 幂等；
- 只消费 D/LEARNING，不吞并 BLUEPRINT / EVIDENCE / RESUME 等 Owner Workflow；
- 学习完成不自动改 Career Facts、Candidate Evidence、Resume；
- 只有 `READY_FOR_REVIEW` 才回到面试复练；
- Learning 内部模型明天单独设计，本契约保持最小稳定。

## 5. 当前学习系统入口

学习系统当前持续融合两类输入：
1. **Market-driven**：现有 JD-driven V0.5 的 Requirement / Priority；
2. **Person-driven**：Learning Inbox 中真实面试暴露的动态 Gap。

目标不是另造题库，而是把 Gap 变成“学习目标 → 资料 → 实验 → 故障/取舍 → 验证 → 回面试复练”的闭环。

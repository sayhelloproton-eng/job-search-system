# Phase 1 SQLite Data Contract

Status: **FROZEN_V0.5**  
Database: `app/db/runtime/job-search.db`  
Runtime baseline: Node.js 24 + TypeScript + `node:sqlite`

## 1. Storage conventions

SQLite 是 Phase 1 唯一业务数据库。
所有表启用 foreign keys；业务时间统一存 UTC ISO-8601 `TEXT`。
布尔值使用 `INTEGER 0/1`；枚举值使用 `TEXT + CHECK`（或等价迁移约束）。
金额以整数最小货币单位/业务约定整数存储，展示文本另存，不使用浮点作为真值。

### SDD Design Decision D-001 — timestamps

`created_at / updated_at / captured_at / verified_at / evaluated_at` 等均使用 UTC ISO-8601 字符串。
UI 再按本地时区展示，数据库不保存模糊本地时间。

## 2. Required tables

Phase 1 必须具有：
`schema_migrations`, `providers`, `jobs`, `job_snapshots`, `job_verifications`, `resumes`, `match_baselines`, `match_terms`, `job_match_results`, `search_runs`。

Phase 1 **没有** `applications` 表。

## 3. `schema_migrations`

字段：`id`, `version`, `name`, `checksum`, `applied_at`。
`version` 唯一；checksum 用于检测已发布 migration 被篡改。

## 4. `providers`

字段：`id`, `code`, `name`, `enabled`, `created_at`, `updated_at`。
`code` 唯一且稳定，例如 `boss`, `liepin`, `zhaopin`, `51job`, `company_site`。
Provider 只是数据源身份；Provider 特有状态不能成为核心 Domain 枚举。

## 5. `jobs`

一行表示一个逻辑岗位的当前规范化 projection。

身份/来源：
`id`, `provider_id`, `external_job_id`, `identity_fingerprint`, `origin_kind`, `source_url`。

展示/规范化：
`title`, `company`, `city`, `district`, `address`, `salary_min`, `salary_max`, `salary_months`, `salary_text`, `experience_min`, `experience_max`, `experience_text`, `education_level`, `education_text`, `employment_type`, `role_family`, `seniority`, `jd_text`, `recruiter_name`, `recruiter_activity`, `recruiter_recently_active`, `published_at`。

`published_at` 表示 Provider 能证明的职位创建/发布时间；不得用 `first_seen_at` 伪装。实时 BOSS CLI discovery 若无法证明发布时间，允许 `published_at = NULL`，但该岗位不得进入“已证明最近 2 个月”集合。`source_url` 仅在 Provider 公共输出能证明时保存；BOSS CLI 未提供时允许为 `NULL`，UI 必须显示“原始详情不可用”，不得根据 `job_id` 猜测或拼接 URL。`recruiter_recently_active` 为 nullable boolean observation，不能替代招聘真实性状态。

决策 projection：
`current_verification_status`, `last_verified_at`, `education_risk`, `education_risk_reason`, `is_viewed`。

历史/审计：
`first_seen_at`, `last_seen_at`, `created_at`, `updated_at`。

约束：
- 当 `external_job_id IS NOT NULL` 时，`(provider_id, external_job_id)` 必须唯一。
- `identity_fingerprint` 非空且在 fallback identity 路径上唯一。
- `origin_kind ∈ {LIVE_DISCOVERY, HISTORICAL_IMPORT}`。
- `current_verification_status` 与 `education_risk` 必须使用冻结枚举。
- Phase 1 live discovery 的 `city` 必须为上海；非上海结果不得写成 `LIVE_DISCOVERY`。
- BOSS 结果若无法证明 `published_at`，不得生成虚构时间通过“最近 2 个月”过滤；真实上海 live search 候选可保留 `published_at = NULL` 入库，但必须与“已证明最近 2 个月”集合区分，并在 `search_runs` 记录缺失证据。

## 6. `job_snapshots`

字段：`id`, `job_id`, `captured_at`, `source_url`, `title`, `company`, `salary_text`, `experience_text`, `education_text`, `location_text`, `jd_text`, `recruiter_activity_text`, `content_hash`, `raw_payload_ref`, `created_at`。

`(job_id, content_hash)` 唯一；相同 material content 不重复形成 snapshot。
`raw_payload_ref` 只能指向已清洗的本地 evidence，不得包含账号/browser secret。

## 7. `job_verifications`

字段：`id`, `job_id`, `verified_at`, `status`, `confidence`, `method`, `page_exists`, `closed_signal`, `contact_action_available`, `apply_action_available`, `recruiter_active`, `recruiter_confirmed`, `evidence_summary`, `error_code`, `created_at`。

该表 append-only；历史 verification 不允许被 UPDATE 成另一事实。
`confidence` 为可解释的置信度值，不能覆盖 status 语义；`BLOCKED` 仍然是 `BLOCKED`。

## 8. `resumes`

字段：`id`, `name`, `direction`, `source_path`, `snapshot_path`, `content`, `content_hash`, `version_label`, `is_active`, `created_at`, `updated_at`。
同一份内容可以被不同方向引用，但每个版本必须保留自己的 hash 与版本标签。

## 9. Matching tables

`match_baselines`：`id`, `name`, `direction`, `description`, `is_active`, `created_at`, `updated_at`。

`match_terms`：`id`, `baseline_id`, `term`, `match_type`, `category`, `weight`, `notes`, `is_active`, `created_at`, `updated_at`。
`match_type` 只能使用冻结的六种类型；`baseline_id` 删除策略必须防止遗留孤儿 term。

`job_match_results`：`id`, `job_id`, `baseline_id`, `rule_score`, `semantic_score`, `final_score`, `excluded`, `education_risk`, `matched_terms_json`, `risk_terms_json`, `excluded_terms_json`, `explanation_json`, `evaluator_version`, `evaluated_at`。

Phase 1 `semantic_score` 必须为 `NULL`；`final_score` 遵循 `02-领域规则.md`。
结果必须保留 evaluator version，不能只覆盖“最新分数”而失去算法变更审计能力。

## 10. `search_runs`

字段：`id`, `provider_id`, `query`, `city`, `filters_json`, `started_at`, `finished_at`, `status`, `found_count`, `new_count`, `updated_count`, `duplicate_count`, `blocked_count`, `error_summary`, `created_at`。

每次 discovery 都应能追溯到一个 run；Provider 被阻断时记录 run 失败/阻断及统计，不把职位批量标为 CLOSED。

## 11. Required indexes

至少覆盖：provider、company、city/district、role_family、education_risk、current_verification_status、first_seen_at、last_verified_at。
`job_match_results` 至少按 `(baseline_id, final_score)` 与 `(job_id, evaluated_at)` 可高效查询。
`job_verifications`、`job_snapshots` 至少按 `(job_id, time DESC)` 可高效形成 timeline。

## 12. Sensitive-data boundary

以下内容禁止进入任何业务表、JSON evidence 或 raw payload：
- cookie / session cookie
- bearer/access/refresh token
- security_id / anti-bot secret
- CAPTCHA solution
- 账号密码、短信验证码
- 浏览器本地认证秘密

若 Provider 原始响应含这些字段，必须在持久化前清洗。BOSS Adapter 可在浏览器运行时短暂使用页面登录态或 `security_id` 完成只读请求，但这些值只能停留在 Provider/Extension 临时边界，禁止进入 Application DTO、业务日志、SQLite 或 evidence。

## 13. Data ownership

`jobs` 保存当前 projection；`job_snapshots` 保存 JD 内容历史；`job_verifications` 保存招聘真实性历史。
三个概念不得合并成一张“万能 jobs 表”。

`resumes` 不是职业事实真源；它只保存可追溯版本快照。
`job_match_results` 不是 JD 真源；它只是 baseline + evaluator version 下的计算结果。

## 14. Schema exclusions

Phase 1 不建立用户账号、多租户、消息、聊天、投递、浏览器 session、模型调用日志等领域表。
如果实现需要这些表才能运行，必须先升级 SDD，而不是在 migration 中偷偷加入。

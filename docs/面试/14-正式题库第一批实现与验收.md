## 1. 本阶段解决什么

Wave 1 不是“开始堆题量”，而是验证正式 Question Corpus 能否真正进入既有 Interview Runtime：

```text
Route
→ Question Family
→ Canonical Question / Pressure Variant
→ Intent / Signal
→ Candidate Evidence / Claim Boundary
→ Scoring Anchor
→ Follow-up Graph
→ FTS5 + Route-aware Retrieval
```

外部 A/B 来源只提供方法、训练结构和评分依据；canonical question 由本项目基于目标岗位、真实 JD 需求、个人 Evidence 与 Claim Boundary 内部编译。C 类面经不得拥有 ACTIVE canonical question。

## 4. 真实问题与修复

第一轮 GREEN 为 `9/10`。FDE 查询“双控制面 / 专有云 / 需求”时，Agent Runtime Family 因 lexical overlap 抢占 Top1。

这不是测试夹具问题，而是 Retrieval 缺少 Route Eligibility Hard Filter。修复后规则为：如果某 Family 已有明确 route-bound Evidence Link，则只有绑定当前 Route 的 Family 才能进入候选集；共享基础 Family 仍可跨路线参与 Graph/Signal 检索。

同时 FTS projection 增加 `evidence:<stable-id>`，使 Route Evidence Rerank 与正式题库保持同一 Evidence 语义。

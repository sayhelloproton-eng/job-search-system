## 1. 本阶段解决什么

Wave 3 补齐正式面试 Corpus 中此前没有覆盖的场景型能力：

```text

FDE Case
Claim Risk Boundary
Candidate Due Diligence
Offer Negotiation
```

这一批首次正式区分两类题：

- **Evidence-required**：JD Role Fit、FDE Case、Claim Risk，必须落到 Candidate Evidence + Claim Boundary。
- **Evidence-optional**：Coding、Candidate Due Diligence、Offer Negotiation，不允许为了统一格式制造“我做过”的经历。

## 4. Retrieval 问题与修复

第一轮 GREEN 为 `9/10`：Claim Risk 的“主导 / 团队 / 本人 / 决策范围”查询被已有前端迁移题抢 Top1。原因是 FTS5 trigram 对多个 2 字中文短词召回弱，而 Claim Risk 跨路线绑定不同 Evidence，不能依赖单一 preferred Evidence bonus。

修复方式不是提高虚假 Evidence 强度，而是在 canonical search metadata 中补中文检索同义标签，让短词组合能形成稳定 trigram 命中。Wave 3 随后达到 `10/10 PASS`。

随后 36 题真实 Corpus 性能实测暴露 `p95=106.621ms`。拆分确认 FTS p95 约 `2.745ms`，主要抖动来自每轮重新 materialize 完整 Question Catalog。

优化保持数据实时性：固定 SQL 使用 prepared statement；Question Catalog 与 Route Metadata 缓存 materialized rows，但每轮用 `COUNT + MAX(updated_at)` stamp 自动判断失效。新增 `TP-CORPUS3-011` 验证“先检索 → 再注册 Wave 3 → 缓存自动刷新”。

最终 36 题 Corpus 实测：

```text
p50 = 1.192ms
p95 = 48.292ms
max = 299.578ms  # 记录为单次 outlier，不作为 p95 Gate
```

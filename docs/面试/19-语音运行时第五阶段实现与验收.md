DB-5 只实现协议中立的 Interview Runtime Service，不接 GPT Realtime，也不实现 MCP / HTTP transport。

本阶段完成：

## 2. 实现真值

实现：`app/server/interview-voice-runtime.ts`。
TDD：`app/tests/interview-voice-runtime.test.ts`。

Runtime 不直接读取 Career Facts 文件，也不让 Voice 自由查询 SQL。Evidence 冷路径只返回 stable ref、canonical locator、short hint 与 Claim Boundary。

`start_session` 创建 Session 并初始化十类 Signal 状态；`next_turn` 使用既有 DB-4 Retrieval Core，结合 Scene policy、Route、全场已问集合、最近多样性、Graph/FTS 与 Evidence Boundary 组装一个 Turn Pack；`observe_answer` 只追加或更新 Runtime State；所有写路径由 `request_id` 恢复幂等结果。

Turn Pack 只包含当前一步需要的：Scene、当前状态、一个主问题、最多两个 Follow-up、可观察 Scoring Anchor、最多三个 Evidence Ref、Claim Boundary、Stop Condition 与 fallback。

## 3. TDD 与缺陷闭环

初始 RED：Runtime 模块不存在，`ERR_MODULE_NOT_FOUND`。

第一轮实现后基础 Gate `4/4 PASS`。扩展到状态回写、Evidence、fallback、性能后为 `7/8 PASS`；失败暴露 DB-4 的真实长 Session 缺陷：`asked` 集合只读取最近 6 Turn，因此第 7 轮以后旧题可能重新进入候选。

修复方式不是扩大 Recent Window，而是拆开两个职责：

- **全场 asked set**：读取整个 Session 的已问 question id，负责绝对去重；
- **最近 6 Turn**：只负责 Family / Evidence diversity penalty。

修复后 `Retrieval + DB-5 = 16/16 PASS`，无候选时返回自然 `RECOVER` Turn Pack，不重复旧题、不向候选人暴露数据库错误。
## 4. 性能与包体

40 次同一 Session 的 warm `next_turn` 文本模拟实测：

```text
p50 = 8.458ms
p95 = 47.487ms
max = 49.481ms
max JSON UTF-8 bytes = 2011
max JSON codepoints   = 1421
```

因此 Runtime 组包满足冻结的 `<150ms` 本地预算。包体远低于现阶段 6000 JSON chars 的保守工程上限；DB-6 接真实 GPT Voice 后仍需用实际模型 tokenizer / tool-call payload 重新校准 600–1200 text-token 目标，当前不伪造 tokenizer 精确值。

最终合并 Gate 为 **126/126 PASS**：Bootstrap、Context Governance、DB、DB-1～DB-5、Candidate Material、Formal Corpus、Retrieval、Repository Layout 全部通过。

首次 126 项长回归曾出现一次 `TP-IDB4-008` p95=89.07ms；同轮 42 题 Corpus p95 Gate 与 DB-5 Turn Pack Gate 均通过，随后 DB-4 隔离测试连续 5/5 PASS。直接对同一 DB 做 5 批 × 80 次 warm benchmark，p95 分别约 `4.46 / 1.92 / 3.20 / 34.82 / 5.10ms`，确认是少量进程调度/GC 尖峰放大了原 40 样本统计。最终没有放宽 `<50ms` 阈值，只把 DB-4 Gate 改为 **20 次预热 + 80 次正式样本**，再次完整回归后 126/126 PASS。

最终机械检查：`PRAGMA integrity_check=ok`、`foreign_key_check=0`、Vector/Embedding table=0、migration 仍仅 `001/002/003`、`git diff --check=PASS`。数据库 ACTIVE Question Family 总数为 25，其中 **21 个是 Formal Corpus Family**；另外 4 个 `qf.build-vs-buy / qf.failure-tradeoff / qf.ownership / qf.unknown-boundary` 是 DB-4 Golden baseline Family，不计入 Formal Corpus V1 的 21 Family。

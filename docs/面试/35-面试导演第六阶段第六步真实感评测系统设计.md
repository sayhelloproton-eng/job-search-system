# 面试导演第六阶段第六步｜真实感评测系统设计

> 日期：2026-09-09
> 状态：**P6_6_SDD_V1 / FROZEN / TRANSCRIPT_REPLAY_FIRST / NO_MIGRATION**

## 1. 目标

P6-6 不新增第二套面试导演，也不以“听起来像真人”作为验收标准。它只验证已经冻结的 P6-1～P6-5 Director 在固定回答轨迹下，能否做出稳定、可解释、符合招聘取证逻辑的 phase / probe / stop 决策。

固定链路：

```text
Frozen Director Plan
+ Transcript Fixture / Structured Answer Observation
→ Existing Interview Runtime
→ Existing Director Decision
→ Semantic Replay Projection
→ Mechanical Realism Metrics
```

Candidate 模型的语言质量、知识水平、措辞自然度不计入 Director 分数。

## 2. Authority 与边界

P6-6 只允许新增：
- 固定 Transcript Fixture；
- 可重复执行的 Realism Eval runner / semantic projection；
- P6-6 tests 与验收报告；
- 若 RED 能追溯到 P6-1 已冻结合同，可对 Director 做最小政策修复。

禁止：
- 新 migration / 新表；
- 新 Director Tool；
- 第二套 Question Bank / Signal / Evidence / Score；
- 为过测试修改 Career Facts、Candidate Evidence 或题库事实；
- 在活动面试输出中暴露 hidden score / reasonCode / hypothesis；
- 把“更严厉”当成更真实。

## 3. 第一版固定评测场景

V1 至少冻结 10 类 fixture：

1. **强回答停止追问**：当前 Signal 已 CONFIRMED 后不得继续同 Signal `PROBE_DEPTH`。
2. **Ownership 含糊**：出现“我们做了”类范围歧义时，必须继续做可证伪 Ownership 验证，而不是直接判弱。
3. **漂亮指标无基线**：强指标 Claim 无验证时优先建立/处理 Claim Debt。
4. **前后矛盾**：结构化 `truth.*` HIGH/FATAL Risk 优先于普通 P0 coverage。
5. **明确不会**：explicit unknown 后不得同义反复深挖。
6. **背诵感/模板感**：只允许触发约束变化类 Challenge，不得直接降低 Signal 或评分。
7. **时间不足**：phase/round hard budget 必须 advance/close，禁止新开低价值深挖链。
8. **角色差异**：Tech1 / HM / FDE 对同一项目上下文必须产生不同 Mission/Phase/Target Signal。
9. **No Coaching Leak**：candidate-visible TurnPack 不包含 score / reasonCode / hypothesis / claim debt 内部字段。
10. **Replay Stability**：相同 plan + transcript + timestamps 的语义 Decision 必须一致；随机 ID 不参与稳定性比较。

## 4. 机械指标

P6-6 V1 指标固定为：

- `STOP_DISCIPLINE`
- `PROBE_COHERENCE`
- `TRUTH_RISK_PRIORITY`
- `EXPLICIT_UNKNOWN_DISCIPLINE`
- `ANTI_SCRIPT_REASONING_CHALLENGE`
- `PHASE_DISCIPLINE`
- `ROLE_DIFFERENTIATION`
- `NO_COACHING_LEAK`
- `REPLAY_EXPLAINABILITY`
- `NO_PERSONA_BIAS`

每个 fixture 必须声明它验证的 metric 和 expected semantic decision。V1 Final Gate 要求所有冻结 fixture PASS；不采用平均分掩盖关键安全/真实性失败。

## 5. Semantic Decision Projection

Replay 比较必须忽略随机标识，只比较决策语义：

```ts
{
  phaseId,
  action,
  targetSignalId,
  preferredFamilyId,
  reasonCodes,
  nextPhaseId,
  elapsedSeconds,
  remainingSeconds
}
```

`id / sessionId / sourceTurnId / hypothesisId / claimDebtId` 不作为稳定性 equality key，但 fixture 可单独要求 hypothesis/claim debt 是否存在。

## 6. Structured Observation Contract

P6-6 不允许 Director 解析自由文本猜意图。真实性线索必须由 Answer Observer 结构化后进入决策：

- Strong Claim：继续复用 `detectedClaims[].strength='STRONG'`；
- Truth contradiction：继续复用 `riskUpdate`，并要求 `riskKey` 使用 `truth.*` 命名空间；
- Explicit unknown：继续复用 Director `explicitUnknown=true`；
- Ownership ambiguity：继续使用可证伪 `hypothesisUpdate`；
- Scripted/template cue：新增最小可选 `reasoningChallenge='SCRIPTED_PATTERN'`，只影响下一步 probe 方式，不修改 Signal/Score。

`SCRIPTED_PATTERN` 的唯一默认裁决：`CHALLENGE_TRADEOFF` + `SCRIPTED_PATTERN_CONSTRAINT_CHANGE`。它不是负面评分事实。

## 7. Truth Risk Priority

P6-1 已冻结：`FATAL/HIGH truth risk needing evidence > unresolved strong Claim > P0 Focus`。

因此 P6-6 若发现现实现未读取 `interview_session_risks`，属于合同缺陷而不是新需求。最小修复规则：
- 仅处理 `status IN (OPEN, REOPENED)`；
- 仅处理 `severity IN (HIGH, FATAL)`；
- 仅处理 `risk_key LIKE 'truth.%'`；
- 动作为 `CROSS_CHECK_CLAIM`；
- target 优先 `signal.truthfulness`，其次 `signal.risk`，再退回当前 turn signal；
- reasonCode 为 `HIGH_TRUTH_RISK_REQUIRES_EVIDENCE`。

普通 delivery/technical risk 不得借此抢占所有 P0 Mission。

## 8. Role Differentiation

角色差异不要求同一句自然语言问题不同，而要求 Director Authority 不同：
- Tech1：真实性、技术下限、实现/Debug；
- HM：未来 Scope、Ownership、Value；
- FDE：客户目标、方案边界、交付 Risk、验收。

评测至少比较 default plan 的 purpose / phases / focus signals，并在 replay 中验证 target signal 不退化成三条路线同一模板。

## 9. No Coaching Leak

内部 Director metadata 可以存在于 trusted runtime response，但 candidate-visible `InterviewTurnPack.prompt` 不得包含：
- `reasonCodes`
- score / verdict
- hypothesis statement/id
- claim debt internal id
- “正确答案/你应该回答”类 coaching 文本

P6-6 只机械验证 Runtime 生成的 TurnPack；自然语言模型仍受 Interview Skill 的“不泄露答案与评分”约束。

## 10. 模型自演练边界

固定 fixture 全绿后才允许模型自演练。自演练至少覆盖 AI Agent Tech1、Advanced FE Deep Dive、ToB/FDE Case。

模型自演练只记录：
- phase timeline；
- Director actions；
- signal evolution；
- stop / pivot / close；
- replay explanation。

Candidate Agent 的答案好坏不进入 Director Realism 机械分。模型自演练发现的问题必须回放成固定 fixture 后，才能修改 Director。

## 11. Gate

```text
SDD FROZEN
→ TDD RED
→ minimal policy fix / eval runner
→ P6-6 targeted fixture gate
→ P6-3/P6-4/P6-5 regression
→ Interview/Learning blast-radius gate
→ full repository gate if production runtime changed
→ P6-6 acceptance
```

P6-6 PASS 后才进入 P6-7 Voice Pilot；P6-8 继续保持真实反馈驱动的持续校准阶段。

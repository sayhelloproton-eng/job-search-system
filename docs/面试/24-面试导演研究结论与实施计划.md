# Interview Director｜面试导演研究结论与实施计划

> 日期：2026-09-08
> 状态：**RESEARCH_COMPLETE / P6_0_TO_P6_6_PASS / P6_7_VOICE_PILOT_READY_AWAIT_USER_VOICE / RUNTIME_INTEGRATED**

## 1. 目标

当前面试成长系统已经具备题库、Route、Scene、Follow-up/Challenge、Growth、Adaptive Training 与 Learning Bridge，但还缺少真正控制整场面试的 **Interview Director**。

导演层解决的不是“问什么”，而是：**这一轮为什么问、面试官在判断什么、为什么继续追、什么时候换题、什么时候换阶段、什么时候收口。**

```text
Question Bank = 可用问题与评分素材
Interview Runtime = 取题、记录、证据与状态执行
Interview Director = 整场面试的决策与节奏控制
Growth System = 面试后的复盘、成长与复练
```

研究阶段已经结束，P6-1～P6-6 已按 SDD/TDD 落地并通过 Realism Evaluation；当前下一门禁为 P6-7 真实用户 Voice Pilot。后续只按既定阶段门禁继续推进，不回退重做已冻结的 Authority。
## 2. 研究范围

本轮从三类材料交叉研究，不以单一 Skill 作为真源。

### 2.1 招聘方 / 结构化面试方法

- OPM Structured Interview：Job Analysis → Competency → Lead Question → Controlled Probe → Anchored Rating。
- Greenhouse Structured Hiring：每轮先定义 Purpose / Focus Attributes；问题只是收集本轮决策所需证据的工具。
- Amazon Interview Loop：不同 Interviewer 被分配不同技术/行为 Competency；SDE/FEE 等岗位采用明确的轮次与时间盒。
- Karat Technical Interview：Rubric + 实时人工追问；AI 时代额外观察 codebase navigation、debugging、requirements、architecture reasoning 与 AI output validation。

### 2.2 可复用 Skill / Agent 设计

- `interviewer-skill`：TechMap + Behavior Archive + Persona + interview/pressure/hint style。
- `interview-system-designer`：Interview Loop、Competency、1–4 Rubric、Scorecard、Calibration。
- `Mock-Interviewer-Skill`：简历风险预判、Ownership/指标真实性/项目细节连续验证。
- `smart-interview-prep`：Session State、Time Budget、Drill Chain、Weakness、Round Type、动态追问限制。
- `cs-tech-interviewer`：JD / Resume / Mode 驱动整场 question plan。
- `system-design-skill`：严格 Phase、Time-box、Deep Dive、Debrief。
- `hiring-manager-deep-dive`：Staff+ 的 Scope / Ambiguity / Influence / Strategic Thinking。

### 2.3 国内真实面经

重点观察 2026 牛客中的高级前端、AI Agent、FDE/AI 应用岗位：项目深挖路径、一二面差异、Coding/System Design 插入点、真实追问深度与时间分布。
## 3. 核心研究结论

### 3.1 真实面试是 Signal-driven，不是 Question-driven

面试官真正拥有的是一组待验证判断，而不是一张必须顺序问完的题单。

```text
Round Mission
→ Focus Signals
→ Lead Question
→ Candidate Evidence
→ Hypothesis / Risk / Claim Debt
→ Probe / Challenge / Cross-check
→ Signal Sufficient ?
→ Pivot / Next Phase / Close
```

### 3.2 结构化目标必须固定，追问可以自适应

高质量面试不是自由聊天，也不是死板朗读题库。核心问题、Competency、评分锚点必须预先确定；追问可以针对具体回答调整措辞，但不能偷偷改变评价标准。

导演因此采用 **Structured Target + Adaptive Evidence Collection**：
- Target Signal / Rubric 固定；
- Probe 的语义类型受控；
- 具体措辞与深度可随回答变化；
- 同一能力达到足够证据后立即停止继续“拷打”。

### 3.3 一轮面试只承担有限 Mission

每轮不应试图验证全部能力。Director 需要给每个 Round 分配少量 Focus Signals；其余 Signal 只作为 incidental evidence，不强制覆盖。
### 3.4 Interviewer Persona 不是“毒舌人设”

导演需要建模的是 **Role Perspective + Mandate + Probe Style + Pressure Policy**，而不是虚构性格。

例如同一个项目：
- Tech1 Engineer：验证基础、实现细节、debug 能力；
- Senior/Staff：验证架构边界、复杂度、trade-off、failure；
- Hiring Manager：验证 scope、ownership、impact、未来可托付性；
- FDE Interviewer：验证客户问题分解、交付、验收、风险与组织接口；
- Leader / Final：验证残余风险、方向一致性、长期价值。

### 3.5 Hypothesis 是追问的核心中间状态

典型内部假设：
- “候选人确实主导了该项目”；
- “这个漂亮指标可能缺少 baseline”；
- “候选人会使用 RAG，但没有诊断 retrieval failure 的能力”；
- “回答听起来完整，但可能是模板化背诵”。

追问不是为了变难，而是为了 **Confirm / Reject / Supersede** 假设。

### 3.6 时间是 Director 的一等状态

导演必须知道本轮总时长、当前 Phase、已消耗时间、剩余必测 Signal。时间不足时禁止继续低价值深挖；Signal 已充分时即使题库还有题也要主动切换。
### 3.7 AI 时代需要 Anti-script Probe，但不能变成猜疑游戏

对过度完整、像背诵的回答，不根据“感觉”扣分，而是改变约束进行验证：
- 改一个业务条件，要求重新决策；
- 让候选人解释为什么不用另一个方案；
- 给出 failure / bad case，让其诊断；
- 让其解释代码、配置、边界或验证方法；
- 追问“如果重来一次会删什么”。

评分仍只依据回答中可观察的 reasoning / evidence，不依据语气、外貌或主观亲和感。

### 3.8 国内真实面试更像“项目锚点 → 连续延伸”

2026 面经显示，高级前端与 AI Agent 技术面经常从项目中的一个词、API、方案或指标连续下钻，随后再切 Coding、基础或 System Design；二面/HM 更重 Scope、方案必要性、系统判断与上限。

FDE 还必须区分岗位子型：
- Engineering-heavy FDE；
- Solution-heavy FDE；
- Delivery-heavy FDE；
- Productization-heavy FDE。

因此不能只有一个统一的“FDE 面试官”。

## 4. 当前系统已有资产

现有系统已经提供 Director 的大部分底座，不需要重构：
- 3 条岗位 Route；
- 10 个 Scene：HR / Tech1 / Deep Dive / System Design / Coding / FDE Case / HM / Cross / Final / Offer；
- 10 个 Signal：truthfulness / baseline / ceiling / scope / ownership / judgment / failure / value / transferability / risk；
- `interview_session_signals`：已经能记录 UNTESTED / PROBING / CONFIRMED / WEAKENED / CLOSED；
- `interview_session_hypotheses`：表已经存在，但目前没有正式写入/演化入口；
- `interview_session_risks` 与 `interview_claim_debts`：已经可持久化风险与待验证 Claim；
- Question Family / Variant / Edge / Scoring Anchor；
- Candidate Evidence + Claim Boundary；
- Growth / Adaptive / Review / Learning Bridge。

现有 `TurnPack` 已经携带 `targetSignal / currentHypothesis / residualRisk / claimDebt / FOLLOW_UP / CHALLENGE`，说明 Director 应作为现有 Runtime 上层，而不是另造面试执行系统。

## 5. 当前真正缺口

1. **Round Mission**：每轮明确要拿到哪些招聘信号。
2. **Focus Signal Set**：不是启动时 10 个 Signal 全等权。
3. **Interviewer Archetype**：Scene 目前只有角色名称，没有具体 mandate / probe policy。
4. **Phase State Machine**：没有开场、项目、基础、Coding、Design、反问等整场状态。
5. **Time Budget**：当前只有单题 seconds/depth target，没有整轮预算与 phase deadline。
6. **Hypothesis Lifecycle**：表存在但没有正式创建、确认、驳回、替换路径。
7. **Autonomous Probe Decision**：当前 FOLLOW_UP / CHALLENGE 主要由 caller 指定。
8. **Signal Coverage Decision**：没有“证据够了就停”的整场裁决器。
9. **Hidden Scorecard**：有 Family Anchor，但没有 Round 级 Focus Attribute Scorecard。
10. **Interview Loop**：Scene 已存在，但没有公司/JD/Level 驱动的多轮编排。
## 6. Director V1 的最小决策模型

每次候选人回答后，Director 只做以下一次决策循环：

```text
Observe Answer
→ Update Signal Board
→ Update Hypothesis / Risk / Claim Debt
→ Check Time Budget
→ Check Focus Signal Coverage
→ Choose ONE Action
```

允许的 Action：
- `PROBE_DEPTH`：继续同一证据链深挖；
- `CHALLENGE_TRADEOFF`：改变约束或质疑方案；
- `CROSS_CHECK_CLAIM`：验证 Ownership / 指标 / 一致性；
- `CLARIFY`：回答含糊但不应直接判弱；
- `PIVOT_TOPIC`：当前 Signal 已足够，换主题；
- `ADVANCE_PHASE`：本 Phase 达成目标；
- `CLOSE_ROUND`：时间或 Mission 已完成；
- `RECOVER`：题库/状态不足时自然降级。

禁止 Action：为了显得严格而无限追问、根据语气直接扣分、在面试中泄露隐藏评分、把学习缺口临时教会后继续冒充真实面试。

## 7. Director 的 Stop Rule

优先停止继续追问，当满足任一条件：
1. 当前 Focus Signal 已获得足够正/负证据；
2. Hypothesis 已 CONFIRMED / REJECTED；
3. 同一 Claim 已经连续验证到边界清楚；
4. 继续追问只会重复已有信息；
5. 时间预算要求切 Phase；
6. 候选人明确不会，且再问同义题不会产生新 Signal。

## 9. Director Corpus：除了题库，还需要“面试过程语料”

题库 Corpus 回答“可能问什么”；Director Corpus 回答“现实中通常怎么问、由谁问、在哪一轮问、追到什么深度”。

建议新增独立的研究资产层，但在 SDD 冻结前先用文档/JSON 原型，不立即建表：
- Company / Team；
- Role / Level；
- Round Type；
- Interviewer Role；
- Duration；
- Phase Sequence；
- Focus Competencies；
- Probe Pattern；
- Coding / Design 是否出现；
- 来源与日期；
- Evidence Grade：`OFFICIAL / MULTI_REPORT / SINGLE_REPORT / INFERRED`。

公司风格只能按证据强度使用：官方 Hiring Guide 高于社区面经；单篇面经只能形成“候选 Pattern”，不能写成“该公司一定这样面”。

### 持续来源

- 官方 Hiring / Interview Prep / Engineering Blog；
- 牛客近期真实面经；
- 公开 Interview Skill；
- 后续用户自己的真实面试 transcript / 回忆；
- JD 与当前岗位职责。

用户自己的真实面试反馈优先级最高，用于校准 Director 的“现实感”，但不用于凭空推断某位具体面试官人格。
## 10. 分阶段实施计划

### P6-0｜Research Freeze

目标：冻结本研究结论、外部方法边界、现有系统 Gap。
状态：**本轮完成，等待用户确认。**

### P6-1｜Director SDD / Domain Model

只做设计，不编码：
- `InterviewLoopProfile`；
- `RoundMission`；
- `InterviewerArchetype`；
- `PhasePlan`；
- `FocusSignal`；
- `ProbePolicy`；
- `DirectorDecision`；
- `RoundScorecard`。

必须先定义每个对象的 Authority、生命周期、与现有 Scene/Signal/TurnPack 的关系，以及哪些状态需要持久化、哪些只在 Session 中派生。

Gate：能用纯数据描述一场 AI Agent Tech1、一场高级前端 Tech2、一场 FDE Case，且不需要新增题目也能说明完整导演决策。

### P6-2｜Director Corpus V1

建立官方招聘资料 + 近期真实面经的“过程语料”，先覆盖三条主路线和常见轮次；定义 source grade、freshness、去重与冲突规则。
### P6-3｜Director Decision Engine

先实现纯决策层，不直接生成自然语言问题：
- 输入：Session / Round / Phase / Focus Signals / Answer Observation / Time；
- 输出：唯一 `DirectorDecision`；
- 自动维护 Hypothesis 生命周期；
- 自动决定 Probe / Challenge / Cross-check / Pivot / Advance / Close；
- 决策必须附 `reasonCodes`，便于测试和复盘。

优先复用现有 `interview_session_signals / hypotheses / risks / claim_debts`；只有 SDD 证明现有表无法表达时才考虑 migration 006。

### P6-4｜Runtime Integration

让 Director 决定 `desiredAction / preferredFamily / targetSignal`，现有 Retrieval 继续负责选题。Director 不直接绕过 Runtime 发明平行题目。

目标链路：

```text
Answer Observation
→ Director Decision
→ Runtime Retrieval
→ InterviewTurnPack
→ AI 只负责自然口语呈现
```

### P6-5｜Interviewer Archetype + Loop Templates

为 10 个现有 Scene 补真正的 interviewer mandate；为三条 Route 建默认 Loop，并允许公司/JD evidence 覆盖默认模板。

Persona 只影响提问方式、压力、hint、打断策略；不得改变同一 Round 的评分标准。
### P6-6｜Realism Evaluation / TDD

先用固定 transcript fixture 验证 Director 决策，不靠“我觉得挺真实”。至少覆盖：
- 强回答：Signal 足够后停止追问；
- 模糊“我们做了”：连续验证个人 Ownership；
- 漂亮指标无 baseline：触发 Claim Cross-check；
- 回答自相矛盾：打开 Risk 并回查；
- 明确不会：记录 Gap，避免同义反复拷打；
- 背诵感回答：改变约束验证 reasoning；
- 时间不足：自动切 Phase / 收尾；
- Tech1 / HM / FDE 对同一项目产生不同追问；
- 面试中不泄露 hidden score / reasonCode；
- 相同 transcript + plan 的 Decision 可解释且基本稳定。

随后做模型自演练：Interviewer Agent + Candidate Agent 跑完整场；只评价 Director 的 phase/probe/stop 决策，不把 Candidate 模型质量混进 Director 评分。

### P6-7｜真实用户 Voice Pilot

最后才用 ChatGPT Voice 真实跑 AI Agent Tech1、高级前端 Deep Dive、FDE Case 三类场景。后台记录 Director Decision、Signal Evolution、Time/Phase Timeline；用户只感知自然面试。
### P6-8｜Real Interview Feedback / Director Self-Calibration

真实面试和后续模拟训练回来后，不只是“收集反馈”，Director 必须先做问题归因：
- `CANDIDATE_KNOWLEDGE_GAP`：知识/术语/机制确实不会 → Learning Inbox；
- `CANDIDATE_EXPRESSION_GAP`：知道但表达、结构或临场组织不稳 → Growth / Expression；
- `QUESTION_CORPUS_GAP`：题目覆盖、难度、追问素材或评分锚点不足 → Question Corpus maintenance；
- `DIRECTOR_POLICY_GAP`：Signal 判断、Probe、Stop、Phase、Timebox、Interviewer mandate 不真实 → Director program change candidate；
- `SCORING_GAP`：证据与 verdict 不匹配 → Scorecard / anchor calibration。

只有证据指向 `DIRECTOR_POLICY_GAP / SCORING_GAP` 时才调整 Director 程序，并必须走 targeted regression / realism replay；单次异常不能直接改全局策略。

同时将实际 Round、Interviewer Role、Phase、Question/Probe Pattern 与 Director 预测对比。一次真实面试只更新 observation；多来源重复或用户本人多轮稳定反馈后，才能升级为稳定 Pattern / company override。

## 11. Director V1 验收指标

不是用“回答听起来像面试官”验收，而是至少满足：
- `Mission Coverage`：本轮 Focus Signals 被有效覆盖；
- `Probe Coherence`：追问能明确追溯到上一答中的 Claim / Gap / Hypothesis；
- `Stop Discipline`：证据足够后不会无意义继续追；
- `Phase Discipline`：时间与阶段切换合理；
- `Role Differentiation`：Tech1 / Staff / HM / FDE 的决策目标可区分；
- `Evidence Grounding`：评分有可观察回答证据；
- `No Coaching Leak`：活动面试阶段不泄露答案和评分；
- `No Persona Bias`：风格不改变评价口径；
- `Route Fidelity`：三条岗位路线表现出不同考察重心；
- `Replay Explainability`：每次 Director Decision 有 reasonCode 与状态依据。

最终再增加用户主观指标：`Perceived Realism`。它用于调节节奏/表达，不覆盖上述机械 Gate。

## 12. 明确不做

- 不把“严厉”当成真实；
- 不做无限追问；
- 不用人格猜测替代岗位 Signal；
- 不根据外貌、口音、紧张程度直接评分；
- 不为 Director 再建第二套 Question Bank；
- 不让 Director 绕过 Candidate Evidence / Claim Boundary；
- 不因为一个社区面经就硬编码公司流程；
- 不在 SDD 冻结前新增数据库表或修改 Runtime。
## 13. 研究来源与吸收策略

### 13.1 官方 / 招聘方方法：作为导演原则真源

- OPM Structured Interview：吸收 Competency → Lead Question → Controlled Probe → Anchored Rating；吸收“可自适应措辞但不得改变 probe 语义”；不吸收与本产品无关的政府流程细节。
- Greenhouse Structured Hiring：吸收 Round Purpose、Focus Attributes、Scorecard 与独立评分；每轮 Focus Signal 默认保持少量，不追求全量覆盖。
- Amazon Interview Prep：吸收多轮 Loop、不同 Interviewer Mandate、明确时间盒；不把 Amazon 的具体轮次数量硬编码为通用标准。
- Karat：吸收 competency rubric、实时 probing，以及 AI 时代对 codebase navigation / debugging / architecture reasoning / AI validation 的重视。

### 13.2 开源 Skill：作为模式库，不作为事实真源

- `interviewer-skill`：吸收 interviewer profile / behavior archive / pressure & hint style 的建模思想。
- `interview-system-designer`：吸收 loop / competency / rubric / calibration。
- `Mock-Interviewer-Skill`：吸收 resume risk hypothesis、ownership/metric cross-check；拒绝“越毒越真实”的表演取向。
- `smart-interview-prep`：吸收 drill chain、pending follow-up、remaining time、max depth 等 Session 状态。
- `system-design-skill`：吸收 phase / time-box / deep dive / debrief。
- `hiring-manager-deep-dive`：吸收 Staff+/HM 对 scope、ambiguity、influence、strategic thinking 的判断框架。
### 13.3 真实面经：作为 Reality Calibration

- 牛客近期高级前端：吸收“项目锚点连续下钻 → 基础/Coding → 收尾”的真实节奏；单篇只做 observation。
- 牛客近期 AI Agent：吸收项目实现、Agent/RAG/Eval、coding 与场景挑战混合出现的现实结构。
- 牛客近期 FDE：吸收 Engineering / Solution / Delivery / Productization 不同子型；拒绝把 FDE 固化成单一岗位画像。
